# 发布与签名

## 结论先说：不上架也已经在签名

Android 强制每个可安装的 APK 都带签名。没有签名的 APK **装都装不上**。

| 构建 | 谁签的 | 用途 |
| --- | --- | --- |
| `assembleDebug` | Android Studio 自动生成的 debug 证书 | 自用、开发、测试 |
| `assembleRelease` | 本仓库的发布密钥库（`keystore/`，不进 Git） | 长期使用、给别人装、以后上架也不换签名 |

不上架就**不需要**：Google Play 开发者账号、Play App Signing、`.aab`、上传密钥、ProGuard mapping 上传。

## 为什么必须固定一份自己的签名

Android 的覆盖升级规则是「同 applicationId + 同签名」。所以签名的实际意义是**升级链**：

- 用 debug 签名：debug 证书在 `%USERPROFILE%\.android\debug.keystore`，换电脑、重装系统、
  或 Android Studio 重新生成它之后，旧包升级会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，
  用户只能卸载重装（本地数据要先导出 JSON）。
- 用自己的发布密钥库：只要 `.jks` 和口令在，任何机器、任何时间都能继续发升级包。

**代价**：这个密钥库丢了就再也发不了升级——没有找回途径，只能换 applicationId 当新应用重发。
所以「密钥库比代码重要」不是夸张。

## 密钥库在哪、怎么备份

| 项 | 位置 |
| --- | --- |
| 密钥库 | `keystore/ledger-release.jks`（PKCS12，RSA 4096，有效期 10000 天） |
| 口令与别名 | `keystore/keystore.properties`（明文，本地文件） |
| 备份说明 | `keystore/README-必读.md` |

这三样都在 `.gitignore` 里（`keystore/`、`*.jks`、`*.keystore`、`keystore.properties`），**绝不提交**。
因为 Git 里没有，所以**必须自己另存一份到仓库之外**（U 盘 / 密码管理器附件 / 私有网盘）。

## 发布步骤

```bash
export JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
cd /d/git/ledger
./gradlew.bat --console=plain testDebugUnitTest --rerun lint   # 门禁先绿
./gradlew.bat --console=plain assembleRelease                  # 产物见下
# 产物：app/build/outputs/apk/release/app-release.apk
# 验签：
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --print-certs app/build/outputs/apk/release/app-release.apk
```

签名配置在 `app/build.gradle.kts`：`signingConfigs { create("release") { ... } }` 从
`keystore/keystore.properties` 读 `storeFile / storePassword / keyAlias / keyPassword`。
文件不存在时（别人 clone、CI）不注册该配置，`assembleRelease` 产出未签名包，
**不影响 debug 构建与单元测试**。

## 版本号与后续约束

- 安装标识：`applicationId = com.nimo.ledger`（2026-10-16 发布定版时从 `com.nimo.bookkeeping` 改来）。
- 源码命名空间：`namespace = com.nimo.bookkeeping`，全部源码目录与 `R`/`BuildConfig` 包名仍用它。
  二者是两回事：`applicationId` 决定「装到手机上是哪个应用」，`namespace` 只是代码组织。
  改 `namespace` 等于把所有源文件重排一遍，没有收益，不动。
- 版本：`versionCode = 1`、`versionName = "1.0"`（2026-10-16 从 `0.1.0` 定为 `1.0`）。
- 因为 `applicationId` 变了，这台手机上旧的 `com.nimo.bookkeeping` 属于**另一个应用**：
  新包是全新安装、与旧包并存，不能覆盖它。要迁移数据：旧包先「导出 JSON 完整备份」，
  新包再「导入 JSON（覆盖替换）」，最后卸载旧包。
- **applicationId 一旦对外发布就不能再改**（改了等于另一个应用，旧包无法覆盖升级）。
- 每次要发布新包，`versionCode` 必须 +1，否则系统拒绝覆盖安装。
- `minifyEnabled` 目前为 `false`（计划里的口径）；要开 R8 需单独验证混淆规则与反射/序列化路径。
